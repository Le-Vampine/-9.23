# 问题一运行环境与跨机复现说明

本说明与 `E.1/README.md`、`配置/第一问流程配置.json` 配套。所列版本是产生当前结果时本机环境的实际记录，不表示其他版本已做等价性验证。提交组件内的数值特征可直接读取；从原始视频完整重算时，还需赛题附件1、下列预训练模型权重与 FFmpeg。为遵守竞赛附件总量不超过 50 MB 的要求，原始 MP4、WAV、模型权重及 Python 环境均不放入压缩包。

## 数据与结果的放置

将赛题原始 `label-100.xlsx` 原样放在 `E.1/输入/原始标签/`，100 个 MP4 原样放在 `E.1/输入/原始视频/<video_id>/<clip_id>.mp4`。不得更改文本、标签、编号或视频内容。第1步脚本还会按当前项目的相邻目录结构对赛题原附件做 SHA-256 对照；换机器时，应把完整原附件放在 `E.1` 的相邻目录并保持赛题原目录结构，或仅调整 `代码/样本清单/建立样本清单.py` 中 `source_video_root` 的路径指向。此项路径调整不涉及修改任何赛题数据。

结果读取只需 Python、NumPy：逐样本主文件位于 `结果/08_原文词级跨模态对齐/逐样本/<sample_id>.npz`，用 `numpy.load(..., allow_pickle=False)` 打开；字段和掩码规则见 `结果/08_原文词级跨模态对齐/对齐规则.json`。`交付候选/100条交付索引.csv` 将每条原视频相对路径、三类输出文件、SHA-256、有效时长、有效词数与维度连在一起。主矩阵是变长原文词序列，未填充；批处理时另建右侧补零的 `padding_mask`，不可把无时间词的零占位误认作有效观测。

## 重跑顺序与异常规则

以 `E.1/README.md` 的逐步命令为准，顺序为：建立清单与原始哈希对照 → 完整解码和WAV分离 → Whisper识别 → 原文/识别词比对、MFA对齐和逐词时间筛查 → 原文 BERT 词向量 → librosa 声学帧 → Face Landmarker 视觉帧 → 按原文词时间聚合 → 全量质量核查。重算可能耗时，提交组件已给出当前全部结果，读取与核查无需重跑模型。

Whisper只提供识别文本和初步词边界；MFA使用完整WAV与 Whisper 转写估计候选词区间。原文词必须依次通过“原文—Whisper”和“Whisper—MFA”的唯一同词映射及边界检查，才写入主时间。当前 1,934 个原文词中有 1,421 个主时间，513 个词按规则保留缺失；三条 MFA 失败样本和两条空转写样本不补造时间。音频/视觉原始逐帧特征仍完整保存。只要引用特征矩阵，就必须同时读取各模态掩码和有效长度。
